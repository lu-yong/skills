## 跟踪类型与结论上下文

`结论`是本 skill 唯一更新的字段。使用 Redmine 返回的 `issue.tracker.name` 和现有字段作为结论结构与事实判断的上下文；本 skill 不因跟踪类型更新其他字段。

## 普通结论

结论必须言简意赅并包含三个要素：

```text
问题原因：
处理方案：
影响范围：
```

有代码补丁时，处理方案应说明实际修改内容，并记录已核实的 Gerrit 数字 change number。

## 问题性质与结论补充格式

常用值及含义：

- `上个版本修改引入`：上个发布版本修改一个问题后引入另一个问题，或上个版本修改不彻底。
- `当前版本修改引入`：当前版本开发修改引入问题、修改不彻底，或当前版本新功能专项测试问题。
- `历史遗留`：从更早版本持续存在到现在的问题。

对 `错误` issue，现有 `问题性质` 有值时，使用该值选择结论结构；字段为空时，由 update skill 按自身确认协议展示 `1`/`2`/`3` 选择提示并严格解析；提示模板与解析契约在 `update-issue-conclusion/SKILL.md`，不在此处重复维护。接受值为单个 `1`、`2` 或 `3`，其它输入重新展示同一组选项；`1` 使用普通结论结构，`2` 和 `3` 分别使用对应的补丁引入结构。该选择只用于本次结论草稿，不更新 `问题性质` 字段。

### 当前版本修改引入、上个版本修改引入

对 `错误` 跟踪类型的上述问题性质，结论还必须说明补丁引入关系，并使用以下结构：

```text
* 问题描述（需求规格）：可选；原任务描述清晰时可以省略。
* 问题原因：由 {{patch(<Gerrit change number>)}} 修改引入。
* 处理方案：
* 影响范围：
* 修改补丁：{{patch(<Gerrit change number>)}}
```

其中 `<Gerrit change number>` 必须使用已通过 Gerrit 查询核实的数字 change number，不使用未经核实的 Change-Id 或本地 Git SHA 代替。

### 规格变更

除基本三要素外，需要记录：

1. 规格变更原因；
2. 变更前后的差异；
3. 变更前后的使用差异示例；
4. 变更后可能影响的方案项目、功能模块、软件系统或芯片型号；
5. 相关修改补丁（如果有）。

### 已拒绝

明确说明拒绝理由，并确认已征得软件版本管理员同意。该事实无法从代码或 Gerrit 推断时，先询问用户。

### 反馈

说明完整的分析流程和结论，并确认已征得任务创建者同意。该事实无法从代码或 Gerrit 推断时，先询问用户。

## 问题归属、接口调整与公版问题类别

问题归属、接口调整和公版问题类别等现有字段可以作为结论事实判断的上下文，但本 skill 不更新这些字段。无法从 issue、提交 diff 和 Gerrit 证据确定影响范围时，在结论中保留待确认表述，不自行补齐。

## 证据与范围

结论中的原因、方案和影响范围以 issue 内容、现有字段语境、本地 Git 提交、提交 diff、Gerrit change 和 patch 为依据。范围涉及通用需求或通用问题时，结论说明已核实的分支、项目、模块、系统或芯片范围；范围尚未建立时，使用准确的待确认表述。
